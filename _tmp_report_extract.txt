Part 1 — Design Language
Visual rules applied consistently across screens. Tokens extracted from the current frontend theme (globals.css and feature CSS).
1.1 Design Principles
#
Principle
What It Means in Practice
1
Progress first
Every learner screen surfaces current topic/lesson status and the next actionable step without an extra click.
2
Gate honestly
Locked practice, pending reviews, and insufficient points show why progress is blocked and what unlocks it.
3
Practice over polish
Learning Path and Practice workspaces prioritise answer submission, feedback, and retry over decorative chrome.
4
One primary action
Each screen emphasises a single primary CTA (Start, Submit, Continue, Join) with secondary actions visually quieter.
5
Mock vs live clarity
UI that still uses mock or stub routes (Classroom, Overview, Materials) must remain navigable but not imply completed product capability.

Part 5 — Responsive Rules
Global rules for all screens. Screen-specific mobile exceptions are recorded in Part 4 only.
5.1 Navigation
Breakpoint
Behaviour
Desktop (≥ 1025px)
Full top navbar; all labels visible; shell max ~1440px
Tablet (768–1024px)
Nav links may collapse (~≤1100px CSS); hamburger opens panel
Mobile (< 768px)
Hamburger overlay drawer; compact auth actions
5.2 Content Layout
Breakpoint
Layout Behaviour
Desktop
Multi-column grids (practice catalog 2–3 col; reading split pane); side-by-side forms where designed
Tablet
2-column grids; reading may retain split or soften; tables/cards reduce columns
Mobile
Single column throughout; auth card full width; practice workspaces stack
5.3 Data Tables
Pattern A — Horizontal scroll: keep columns; sticky first column when 5+ columns. Use for dense score/item review tables.
Pattern B — Card reflow: each row becomes a card showing 3–4 key fields. Prefer for entity lists (topics, catalog cards already use cards).
MVP screens primarily use cards/lists rather than wide data tables; choose Pattern B for any future tabular topic/test history.
5.4 Typography Scaling
Breakpoint
Heading Adjustment
Desktop
Full type scale as Part 1.3
Tablet
heading-1 may reduce toward heading-2 size; body unchanged
Mobile
heading-1 → ~24px; heading-2 → ~20px; body sizes unchanged
